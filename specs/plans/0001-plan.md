## Risks & open questions
1. **Race condition on the overlap check.** Two concurrent `createBooking` calls for the same
   overlapping slot could both pass an application-level check before either commits, violating
   BR-1 (a *Key Domain Invariant*, not just a nice-to-have). **Recommendation:** enforce the
   no-overlap rule at the database level too, via a Postgres exclusion constraint on
   `(roomId, tstzrange(startTime, endTime)) WHERE status = 'active'` (requires the `btree_gist`
   extension), in addition to the application-level check that produces a friendly
   `ConflictError`. Cheap to add now in the first migration; expensive to retrofit once real data
   exists. *Needs your approval — this is the one piece of this plan that touches infrastructure
   beyond what the spec explicitly asked for.*
2. **Package manager.** Not specified in bootstrap. **Recommendation:** npm (matches
   `scripts/check.conf.example`'s convention and needs no extra tooling). Flag if you want
   pnpm/yarn instead.
3. **Tests need a real Postgres**, not a mock — the exclusion constraint from Risk #1 is a
   Postgres-specific behavior that a mocked Prisma client can't verify, and `docs/testing.md`
   requires tests to assert real behavior. **Recommendation:** tests run against a local/CI
   Postgres via `DATABASE_URL`, with each test file truncating its tables in `beforeEach`. CI gets
   a `postgres:` service container in `check.yml`.
4. **"Acting user" seam.** No session exists yet (auth is a later spec). **Recommendation:** the
   route layer resolves the acting `userId` from a request header (e.g. `x-acting-user-id`) set by
   the UI's selector, and passes a plain `userId` string into the service layer. When real Auth.js
   sessions arrive later, only `lib/http/acting-user.ts` changes — service function signatures
   don't, per the layering in `docs/architecture.md`.
5. **Overlap semantics as SQL**, to make sure build matches the spec's AC-7 exactly: a candidate
   Booking `[start, end)` overlaps an existing active Booking `[s, e)` for the same room iff
   `start < e AND end > s`. This makes an exact touching boundary (`end == s` or `start == e`)
   **not** a conflict, matching AC-7.
